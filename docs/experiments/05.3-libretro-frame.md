# Stage 5.3 — SameBoy single-frame display

Status: complete. The standalone implementation and physical PW5 display test
are verified. The experiment does not change `src/main.c`, `tools/touch_probe.c`,
the SameBoy submodule, or the existing virtual controls.

## Scope and smallest path

The smallest independent experiment is a new display probe, built separately
from `src/main.c`, that loads the already validated SameBoy Libretro core,
executes a finite warmup, retains a post-warmup video frame, converts it to
Kindle's preferred grayscale input, and displays it once through the existing
vendored FBInk API. Audio and input callbacks remain no-ops. No image file, PNG encoder,
SDL, GTK, touchscreen, or new runtime dependency is needed.

The probe keeps the Libretro lifecycle and the FBInk lifecycle separate:

1. Load the core and ROM, install callbacks, and accept XRGB8888.
2. Run through a finite warmup period, then retain the latest valid video
   callback until the frame limit is reached.
3. Stop using the core frame pointer; optionally unload/deinitialize SameBoy.
4. Open FBInk, save the current screen, render the retained grayscale frame,
   request one refresh, wait for completion, and restore the saved screen on
   normal exit or recoverable failure.

## 1. Libretro video callback

The Libretro callback is:

```c
void video_refresh(const void *data,
                   unsigned width,
                   unsigned height,
                   size_t pitch);
```

`data` points to the current frame for the duration of the callback. `width`
and `height` are in pixels; `pitch` is the number of bytes between rows and
must be used instead of assuming tightly packed rows. A core may call the
callback with `data == NULL` to request duplication of the previous frame.
The capture path ignores such callbacks and all frames during warmup.

The pinned SameBoy core requests `RETRO_PIXEL_FORMAT_XRGB8888`, stores pixels
as `uint32_t`, and calls the callback with `width * sizeof(uint32_t)` as the
pitch. The physical Stage 5.2 run confirmed `160x144` and `640` bytes, but the
probe should still honor the callback arguments rather than hardcode them.

## 2. Safe one-frame retention

The callback pointer must not be retained after returning. Allocate an owned
buffer after validating the dimensions and `pitch` with checked multiplication:

- require non-zero, bounded `width` and `height`;
- require `pitch >= width * 4` for the accepted XRGB8888 format;
- allocate `height * width * sizeof(uint32_t)` with overflow checks;
- copy each row with `memcpy`, from `((const unsigned char *)data) + row * pitch`
  into a packed buffer;
- mark the frame complete only after every row has been copied.

Copying row by row preserves correctness if a future core pads its rows. The
callback ignores non-null frames during warmup, then replaces the owned copy
with each latest valid frame. It does not call FBInk or perform a screen
refresh while the core is inside `retro_run`.

For the tested 160x144 frame, the packed XRGB8888 copy is 92,160 bytes. The
capture buffer remains valid after `retro_run`, `retro_unload_game`, and
`retro_deinit`.

## 3. XRGB8888 to grayscale

SameBoy's XRGB8888 value is `0x00RRGGBB`; the high byte is unused. The capture
code can use `memcpy` into a `uint32_t` before extracting channels, avoiding
unaligned loads and strict-aliasing assumptions:

```c
uint8_t r = (uint8_t)(pixel >> 16);
uint8_t g = (uint8_t)(pixel >> 8);
uint8_t b = (uint8_t)pixel;
uint8_t y = (uint8_t)((77U * r + 150U * g + 29U * b + 128U) >> 8);
```

The integer coefficients approximate the standard luma weights
`0.299R + 0.587G + 0.114B`. Store the result as Kindle YA: one luminance byte
followed by an opaque alpha byte (`0xff`). This matches the existing
`src/main.c` buffer convention and FBInk's documented preferred Kindle raw
input. A Y-only buffer with `ignore_alpha = true` is also possible, but YA is
the smallest change from the validated project path.

## 4. FBInk display API

Use `fbink_print_raw_data()`, not `fbink_print_image()`. The frame already
exists in memory, so a temporary image file and decoder would add complexity.
FBInk accepts Y/YA/RGB/RGBA raw buffers and infers the input component count
from the exact `len / height / width`; the YA buffer length must therefore be
exactly `width * height * 2` with no padding.

The independent probe should follow the existing project sequence:

```c
int fbfd = fbink_open();
FBInkConfig config = {0};
FBInkConfig refresh_config = {0};
FBInkState state = {0};
FBInkDump dump = {0};

fbink_init(fbfd, &config);
fbink_get_state(&config, &state);
fbink_dump(fbfd, &dump);

config.is_cleared = true;
config.no_refresh = true;
fbink_print_raw_data(fbfd, gray_ya, 160, 144, gray_ya_size,
                     0, 0, &config);

refresh_config.is_flashing = true;
fbink_refresh(fbfd, 0, 0, 0, 0, &refresh_config);
fbink_wait_for_complete(fbfd, LAST_MARKER);
```

All return values must be checked. On failure after `fbink_dump`, attempt
`fbink_restore` before freeing the dump and closing the framebuffer. The dump
must be zero-initialized and released with `fbink_free_dump_data()`.

## 5. Aspect-preserving scale

The Game Boy frame is `160:144`, or `10:9`. FBInk's `scaled_width` and
`scaled_height` support aspect-preserving scaling when exactly one dimension is
specified, and support fitting inside the viewport when both are less than
`-1`. The least custom code is therefore:

```c
config.scaled_width = -2;
config.scaled_height = -2;
config.halign = CENTER;
config.valign = CENTER;
```

On the measured PW5 viewport (`1236x1648`), this fits the frame to about
`1236x1112`, centered vertically, without stretching. A fixed `scaled_width`
such as `960` and `scaled_height = 0` would produce `960x864` and reduce the
cost of scaling while preserving the same aspect ratio. The first experiment
should use FBInk's fit-to-viewport behavior and record the observed result;
manual scaling should only be added if the device output exposes a problem.

## 6. One refresh and restoration

Set `is_cleared = true` and `no_refresh = true` for the raw write. Clearing
prevents the margins around the centered frame from retaining unrelated
previous framebuffer contents; FBInk also expands the resulting refresh region
to the full screen. On the PW5/MTK path, the clear is a framebuffer fill and
the `no_refresh` flag suppresses its display update. Then issue one explicit
`fbink_refresh()` with `is_flashing = true` as the existing renderer does. The
zero region requests a full-screen refresh and avoids relying on guessed
Kindle-specific update coordinates. This one-refresh behavior should still be
confirmed in the first hardware run because legacy Kindle branches can handle
clears differently. Wait with
`fbink_wait_for_complete(fbfd, LAST_MARKER)` before teardown.

Call `fbink_dump()` before drawing and `fbink_restore()` after the refresh on
normal termination and recoverable errors. This preserves the existing
ownership model. SIGKILL, power loss, or a process crash cannot guarantee
restoration and remain known limitations.

## Implementation

The implementation is `tools/libretro_frame.c`. It reuses the Stage 5.2
dynamic Libretro loading pattern and links the existing minimal FBInk archive;
it has no dependency on RetroArch, SDL, GTK, touchscreen code, or audio
output. Its lifecycle is deliberately finite:

1. Load the core and ROM and negotiate XRGB8888.
2. Run the configured total frame budget, with a default warmup of 180
   `retro_run()` calls.
3. After warmup, replace the owned copy with each latest valid callback,
   preserving the callback pitch while copying.
4. Convert the final retained frame to YA grayscale and print luminance
   statistics and an FNV-1a 64-bit hash before tearing down SameBoy.
5. Save the current framebuffer, draw the YA image with FBInk, request one
   explicit full-screen flashing refresh, and wait for completion.
6. Hold the displayed image for a configurable time, then restore the saved
   framebuffer and release all resources.

The default hold time is 10 seconds so the image remains observable. A
`SIGINT`, `SIGTERM`, or `SIGHUP` requests early restoration. A zero hold time
is available for cleanup tests, but intentionally restores immediately. The
default total frame budget is 240 and the default warmup is 180; the total
budget must be greater than the warmup value.

The command line is:

```text
libretro_frame CORE ROM [frames] [hold_seconds] [--warmup FRAMES] [--capture-only]
```

`--capture-only` exercises core loading, frame copying, and grayscale
conversion and diagnostics without opening `/dev/fb0`; this is the host-side
test mode. `--warmup` overrides the default 180-frame warmup. The display path
uses `is_cleared=true`, `no_refresh=true`, centered `-2/-2` fit-to-viewport
scaling, and then an explicit full-screen `fbink_refresh()`. The source pitch
is used only while copying the callback; FBInk receives a tightly packed YA
buffer.

## Build and deployment

Host build and capture-only smoke test:

```sh
make host-libretro-frame
make sameboy-core-host
build/libretro_frame-host \
  build/sameboy/sameboy_libretro.so \
  third_party/sameboy/.github/actions/dmg-acid2.gb \
  240 0 --warmup 180 --capture-only
```

ARMv7 build through the existing Docker/toolchain workflow:

```sh
make docker-build-libretro-frame
make deploy-libretro-frame
```

This creates the separate `build/libretro-frame-deploy/` directory containing
`libretro_frame` and `sameboy_libretro.so`. A Kindle deployment and execution
using the existing SSH setup is:

```sh
ssh kindle 'mkdir -p /mnt/us/inkboy/stage53'
scp -O build/libretro-frame-deploy/libretro_frame \
  build/libretro-frame-deploy/sameboy_libretro.so \
  kindle:/mnt/us/inkboy/stage53/
ssh kindle 'cd /mnt/us/inkboy/stage53 && ./libretro_frame \
  ./sameboy_libretro.so \
  "/mnt/us/games/Pokemon - Yellow Version - Special Pikachu Edition (USA, Europe) (GBC,SGB Enhanced).gb" \
  240 10 --warmup 180'
```

The command is a physical display test only after the image is observed on the
PW5. Core execution and a successful FBInk call alone do not prove that the
panel produced the expected image; the observation is recorded below.

## Verification

### Physical Kindle PW5 result

Verified on a Kindle Paperwhite 5 running firmware 5.19.2 with the pinned
SameBoy 1.0.4 core and a Pokémon Yellow `.gb` ROM:

- SameBoy loaded the ROM and produced an XRGB8888 frame after the configured
  warmup.
- The captured frame was `160x144` with a `640`-byte pitch and was converted
  to packed grayscale/YA.
- FBInk successfully displayed the Nintendo boot logo on the physical E-Ink
  screen.
- The image remained visible during the configured hold period and disappeared
  when the probe restored the previous screen.

This confirms the complete Stage 5.3 path: core execution, post-warmup frame
capture, XRGB8888-to-grayscale conversion, FBInk submission, one explicit
refresh, and normal restoration. It does not establish a continuous game
rendering loop or any sustainable display frame rate.

The original white-screen result was caused by capturing the first video
callback too early. The old frame-limit diagnostic also reported a configured
limit as if it were the number of executed frames. The probe now warms up for
180 `retro_run()` calls, retains the latest valid frame afterward, and reports
the measured run and callback counters. This removed the blank-frame condition
in the physical test.

### Host and static verification

The host capture-only smoke test completed with the pinned SameBoy core:

```text
environment: SET_PIXEL_FORMAT requested=1 accepted
capture: first post-warmup frame width=160 height=144 pitch=640 bytes=92160
captured format=XRGB8888 dimensions=160x144 pitch=640 bytes=46080 warmup=180 runs=240 callbacks=240
grayscale min=0 max=255 average=189.048 below_250=10191 hash=fnv1a64:200522295dc28f1c
```

The `runs` and `callbacks` fields are measured counters, not configured
limits. A valid source frame must be judged from the grayscale range,
`below_250` count, and hash; geometry and a successful FBInk return value do
not establish that the captured frame contains visible game graphics.

The ARM artifacts were inspected with `file`, `readelf`, and `nm`:

```text

interpreter: /lib/ld-linux-armhf.so.3

```

The host executable and host SameBoy core remain separate x86-64 artifacts;
the Makefile builds the core in `build/sameboy-work-host` and
`build/sameboy-work-kindle` respectively.

## Risks and unanswered questions

- The physical test verifies one boot-logo frame, not continuous gameplay or
  sustained display performance.
- The callback contract permits variable geometry, padded pitch, and duplicate
  frames. The new probe must validate all three cases even though SameBoy's
  current output is fixed at 160x144 and 640 bytes.
- Full-viewport scaling and the full flashing refresh are verified for this
  single-frame test, but their cost and suitability for continuous rendering
  remain Stage 5.4 questions.
- `fbink_restore()` cannot recover a display after SIGKILL, power loss, or a
  process crash. The probe holds the image by default specifically to make
  observation possible before normal restoration.
- The display probe must remain a separate target and executable. It does not
  add Libretro or frame-loop logic to `src/main.c`, and it does not reuse
  the existing virtual-control path.
