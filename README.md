# InkBoy

Minimal native C application for a jailbroken Kindle Paperwhite 5.

The current M5 prototype integrates Pokémon Yellow through a pinned SameBoy
Libretro core, virtual touchscreen controls, and a minimal statically linked
FBInk renderer. Presentation remains single-threaded with a conservative 1 FPS
full-screen refresh. Gameplay, control response and normal shutdown/restoration
have been validated on the physical PW5; Power is not a controlled exit.

## Build

Docker is the build environment; it is not needed on the Kindle.

```sh
# Download the KindleHF toolchain and generate its Kindle SDK sysroot.
# The SDK setup needs privileged Docker because it mounts the downloaded
# firmware image while extracting the runtime libraries.
make bootstrap

# Cross-compile build/inkboy for the KindleHF ABI.
make kindle

# Inspect the resulting ARM ELF and its dynamic dependencies.
make inspect
```

`make bootstrap` is intentionally separate from `make`: it is a one-time,
networked setup step and can take a while. The generated toolchain and SDK are
ignored by Git. If privileged Docker is unavailable, generate the Kindle SDK
on a Linux host using the KindleModding instructions and point the build at
that toolchain/sysroot instead of using the bootstrap helper.

For a local source/link smoke test only:

```sh
make host
```

The host build is not evidence that the Kindle ABI or runtime libraries are
compatible.

## Device deployment

The repository targets a Kindle Paperwhite 5 (11th generation) with firmware
5.19.2. The deployment helper uses the existing `kindle` SSH alias from
`~/.ssh/config`:

```sh
make deploy PROFILE=baseline
```

It installs under `/mnt/us/inkboy/runs/<run-id>`, verifies the package, then
creates or updates **InkBoy** in the Kindle library to open that run. Existing
runs are preserved and the Kindle root filesystem is not modified.

## Development and profiling workflow

The root Makefile is a command facade; build rules are grouped under `mk/`.
The main commands are:

```sh
make host                        # Host development build
make test                        # Host unit and profile-policy tests
make libretro-runtime-test       # Runtime smoke test with SameBoy
make libretro-scale-test         # Scaler correctness/performance check
make kindle                      # ARM build through Docker
make inspect                     # Inspect the Kindle ELF
make package PROFILE=gc16-2-60   # Build an isolated package and manifest
make deploy PROFILE=gc16-2-60    # Build, install, and update the library shortcut
make run RUN_ID=generated-id    # Use the ID printed by make deploy
make stop RUN_ID=generated-id   # Send SIGTERM and wait for cleanup
make collect RUN_ID=generated-id # Copy its log and manifest to build/results/
python3 tools/profile_report.py build/results/generated-id/runtime.log
```

`PROFILE` accepts `baseline`, or `auto|gc16` with FPS `1|2|4|8` and cleanup
interval `30|60` (for example `auto-1-60`). A unique `RUN_ID` is generated by
default and printed by `make deploy`; pass that exact ID to `run`, `stop`, and
`collect` so they address the installed package.
Packages contain the app, SameBoy core, metadata manifest, and SHA-256
checksums. The app is compiled with that run's remote core path. The maintained
build commands are `host`, `kindle`, and `bootstrap`; historical experiment
commands were removed, while their results remain under `docs/experiments/`.

The defaults are `KINDLE_SSH_ALIAS=kindle` and
`KINDLE_REMOTE_ROOT=/mnt/us/inkboy`; Make exports both to the deploy helper.
Override either once in the environment when needed, for example
`KINDLE_REMOTE_ROOT=/mnt/us/inkboy make deploy ...`. Installation fails if the
run ID already exists on the device.

Every successful `make deploy` (or `bin/deploy install RUN_ID`) installs the
library shortcut at `/mnt/us/documents/InkBoy.sh`. Open **InkBoy** in the Kindle
library and use the on-screen **EXIT** control to leave the game. This requires
the existing Hotfix [scriptlet support](https://kindlemodding.org/kindle-dev/scriptlets.html)
and `flock` on the device; no KUAL extension is required.

`bin/InkBoy.sh` is a template rendered by the deploy helper with the installed
package path and configured remote root. Do not copy the template manually.
The package stays at its original path because its core path is compiled in.
After package and shortcut checksum verification, the helper replaces the
library shortcut atomically. A failure before replacement preserves the previous
shortcut; an already installed package may remain for diagnosis. A new deploy
needs a fresh run ID. Updating the shortcut does not interrupt a running game;
exit and reopen it to use the new version.

The library launcher prevents duplicate library launches with a file lock and
writes the latest session to `$KINDLE_REMOTE_ROOT/launcher.log` (by default
`/mnt/us/inkboy/launcher.log`). SSH `run`, `stop`, and `collect` retain their
separate per-run profiling workflow and logs; do not start an SSH run while a
library session is open. Deployment selects a version but does not launch it.

The gameplay build uses fixed core/ROM paths; it stops through EXIT, SIGINT,
SIGTERM, SIGHUP or a runtime error and attempts framebuffer restoration. The
default core path is `/mnt/us/inkboy/sameboy_libretro.so`;
the ROM is the Pokémon Yellow file under `/mnt/us/games` specified in `main.c`.
The gameplay path's physical matrix is recorded in the
[TASK-009 runtime report](docs/experiments/09-gameplay-runtime.md). Historical
TASK-010 profile measurements remain in the
[presentation fluidity report](docs/experiments/10-presentation-fluidity.md).

## Stage 5.4 benchmark status

Stage 5.4.4 is complete and physically validated on a Kindle Paperwhite 5
running firmware 5.19.2 with SameBoy 1.0.4 and Pokémon Yellow. The optimized
nearest-neighbor scaler reduced measured scaling time from 186.221 ms to
23.140 ms, approximately 87.6%; combined scaling and FBInk draw cost fell
from approximately 207.167 ms to 44.108 ms, approximately 78.7%.
All nearest-mode runs rendered successfully with zero refresh failures and
successful screen restoration. The user preferred nearest visually for its
pixelated Game Boy appearance. Smooth remains the CLI default pending final
confirmation of a future default switch. Full results and decisions are
recorded in [the Stage 5.4 experiment](docs/experiments/05.4-libretro-continuous-rendering.md).

The live probe is a benchmark frontend, not a playable InkBoy integration:
emulation remains below SameBoy's nominal 59.73 FPS, synchronous E-Ink
completion blocks the single-threaded loop, CPU usage remains relatively high,
sustainable higher display rates are unvalidated, and no objective ghosting
measurement has been performed.
